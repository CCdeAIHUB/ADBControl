# 设备预览触控坐标映射

## 目标

桌面端在手机、平板、横竖屏、截图预览、scrcpy 投屏和 Companion MediaProjection 投屏下，必须把指针位置映射到当前可见画面的同一内容位置，不能混用截图、编码帧与物理屏幕的尺寸。

## 根因证据

- M2105K81AC 的物理截图为 `1600x2560`，scrcpy 按投屏配置输出 `800x1280`；
- 故障日志中视频会话报告 `800x1280`，触控却出现 `1301,2208` 等截图坐标；
- 旧实现让截图刷新与实时视频共用一个尺寸字典，在途截图可在投屏启动后覆盖视频尺寸；
- scrcpy 发送端随后把越界坐标静默钳制到 `799,1279`，所以点击集中落到画面边缘。

## 坐标空间

1. 截图预览使用当前 PNG 原始尺寸。
2. 活动投屏只使用当前视频会话报告的帧尺寸；帧尺寸未就绪时拒绝触控，不回退到旧截图尺寸。
3. `Stretch.Uniform` 的内容区域按真实宽高比居中计算，黑边点击不注入设备。
4. scrcpy 坐标和控制消息中的宽高必须来自同一个视频帧坐标空间；越界输入直接失败，禁止静默钳制。
5. Companion 投屏发送编码帧坐标，并通过 `coordinateWidth`、`coordinateHeight` 声明来源空间；Android 端按当前屏幕尺寸等比映射。
6. 边缘映射采用 `(targetExtent - 1) / (sourceExtent - 1)`，确保首尾有效像素精确对应。

## 手势生命周期

- 指针按下时锁定触控后端和起始坐标空间，手势期间不切换到另一后端；
- 点击与滑动使用桌面 DIP 距离判定，避免高分辨率设备放大鼠标轻微抖动；
- 旋转导致坐标空间变化时，不把同一次手势跨空间发送；
- 指针取消或捕获丢失时，scrcpy 发送零压力 `ACTION_UP` 清理上游指针，Companion 删除尚未提交的缓冲手势；
- 停止截图预览时同时失效请求、哈希与截图尺寸，避免旧异步结果污染新会话。

## Companion 兼容策略

`coordinateWidth` 与 `coordinateHeight` 是成对可选字段。两个字段都缺失时继续把触控参数解释为当前物理屏幕坐标；只提供一个字段、字段非正数或坐标越界时返回 `COMPANION_INVALID_ARGUMENT`。

## 可观测性

`%LOCALAPPDATA%\ADBControl\logs\scrcpy.log` 记录触控实际坐标及帧宽高。坐标空间变化和 Companion 指针取消记录 `app.control.touch_dropped` 及原因，但不记录原始设备 ID。

## TDD 场景

- 场景：`1600x2560` 截图与 `800x1280` 活动视频并存时必须选择视频空间；
- 场景：正方形视口中的竖屏视频中心与右下边缘必须准确映射，左右黑边必须拒绝；
- 场景：投屏已激活但帧尺寸无效时不能回退截图坐标；
- 场景：scrcpy 越界坐标必须抛错，不能钳制到边缘；
- 场景：桌面轻微抖动仍为点击，超过 DIP 容差才为滑动；
- 场景：旋转改变坐标空间时必须保留最后一个同空间位置；
- 场景：Companion 编码帧中心和边缘必须映射到物理屏幕中心和边缘。
