# ADR 0004：AI 全局设备上下文、结构化错误与受控交互

- 状态：Accepted
- 日期：2026-08-15
- 修订：2026-08-16

## 上下文

AI 对话原先与当前设备详情页强绑定，即使用户只查询设备清单也会被要求先打开详情。设备截图会被无条件转换为 `image_url`，导致文本模型连续返回 HTTP 400。失败被保存成普通 AI 消息，既没有稳定错误码、日志和系统通知，也会污染后续模型上下文。滚轮处理则只覆盖部分显式注册的 `ScrollViewer`，原生子窗口消息未被路由。

## 决策

1. 由 `DeviceService` 实现 `IAiDeviceInventory`，为 AI 提供设备快照；`device_list` 始终可用，设备操作通过可选 `deviceId` 解析目标。
2. 由 `AiConversationPolicy` 构造全局设备与交互规则，不再把“未打开详情页”解释为“没有设备上下文”。
3. 主对话提供 `ask_user_choice` 工具，仅支持有限单选/多选；自由文字继续使用普通对话回合。
4. 由 `AiProviderCompatibility` 在请求序列化前应用供应商能力策略，并仅对明确图像不兼容的 400 进行一次受控回退。
5. 由 `AiRequestFailureClassifier`、`AiRequestException` 和 `AiRequestLogger` 建立稳定错误合同；UI 使用专用错误卡、应用内通知和 Windows AppNotification。
6. 错误、警告和选择卡可持久化展示，但不重建为模型对话历史。
7. 由 `MouseWheelScrollPolicy` 统一滚轮方向、边界和延迟兜底判定；桌面根元素和每个滚动容器以 handled-events-too 方式接收 XAML 滚轮路由，同时监听 Win32 原生滚轮消息。若两条路径均未收到物理滚轮，则由 `LowLevelMouseWheelInput` 以 `WH_MOUSE_LL` 观察光标下属于当前进程的窗口。所有原生路径均保留系统默认处理，不吞消息；低级事件短时合并并在偏移未变化时才按累计 delta 兜底。刷新 WndProc 钩子时读取真实过程，释放时只还原仍由本程序持有的代理。
8. 设备预览由 `DevicePreviewPresentation` 决定展示，连接状态高于锁屏状态。
9. AI SSE 读取和 JSON 分片解析在线程池执行；`AiStreamRenderPolicy` 控制刷新频率和思考预览长度。完整缓冲只在完成、取消或工具交互边界物化，自动滚动不再同步强制布局。

## 备选方案

- **要求用户关闭自动截图**：把供应商兼容责任转嫁给用户，且不能覆盖工具执行后的自动截图，拒绝。
- **所有 400 都删除图片重试**：可能重复发送无效或有副作用的请求，并掩盖鉴权/参数问题，拒绝。
- **维护当前详情页强绑定**：无法满足全局设备查询和跨设备工具调用，拒绝。
- **为每个页面分别补滚轮事件**：容易遗漏动态页面、嵌套区域和子 HWND，维护成本高，拒绝。
- **低级钩子直接吞掉本应用滚轮**：会破坏 WinUI 默认行为和辅助功能，且增加全局输入风险，拒绝；只观察、过滤当前进程并延迟去重。
- **每个 SSE token 都更新完整 TextBlock**：长思考会形成平方级字符串与布局开销并阻塞 UI，拒绝。
- **只显示原始异常文本**：信息噪声大、不可恢复、无稳定诊断合同，拒绝。

## 结果

- 文本模型不会再收到已知不兼容的图像内容。
- 用户可在不打开详情页时查询设备，并在真正执行操作时再选择目标。
- 错误既可简洁理解，也可用 `traceId` 和脱敏日志完整诊断。
- 内联选择保持在同一回复过程内，同时限制为可验证的有限输入。
- 所有滚动区域共享同一输入路由，嵌套边界行为一致。
- 新供应商、新设备连接方式和新错误类型应扩展策略/分类类及测试，而不是在 `MainWindow` 内增加字符串特判。
